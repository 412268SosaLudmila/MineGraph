1. Introducción

El presente trabajo práctico desarrolla MineGraph, un sistema web de análisis de redes sociales aplicado a un servidor de videojuego Minecraft. El sistema permite visualizar y consultar las relaciones entre jugadores: amistades, rivalidades, transacciones comerciales, pertenencia a clanes y participación en eventos.

Se eligió el área de juegos en línea y seguimiento de estado (ítem 6 del enunciado) como dominio de aplicación, ya que presenta de forma natural el tipo de problema que las bases de datos de grafos resuelven mejor: entidades altamente interconectadas con relaciones de distintos tipos y propiedades propias.

¿Por qué Neo4j?

En un servidor con cientos de jugadores, preguntas como "¿quiénes son los amigos de mis amigos?" o "¿cuál es el camino más corto entre dos jugadores?" requieren recorrer relaciones en profundidad. En una base de datos relacional esto se traduce en múltiples JOINs anidados que se vuelven costosos a medida que crece la red. Neo4j almacena esas relaciones de forma nativa como parte del grafo, permitiendo recorrerlas en tiempo constante independientemente del tamaño total de la base de datos.

3. Consultas Cypher

Consulta 1 — Jugadores online en este momento
Obtiene todos los jugadores cuyo estado actual es online.
MATCH (j:Jugador) WHERE j.estadoOnline = true RETURN j.nickname, j.nivel, j.titulo
Consulta 2 — Top jugadores PvP por ratio K/D
Calcula el ratio kills/muertes y ordena de mayor a menor. Solo considera jugadores que murieron al menos una vez.
MATCH (j:Jugador) WHERE j.muertes > 0 WITH j, toFloat(j.kills) / toFloat(j.muertes) AS kd ORDER BY kd DESC LIMIT 10 OPTIONAL MATCH (j)-[:PERTENECE_A]->(clan:Clan) RETURN j.nickname, kd, clan.nombre
Consulta 3 — Top comerciantes por volumen total
Suma el volumen de todas las relaciones COMERCIA_CON de cada jugador.
MATCH (j:Jugador)-[r:COMERCIA_CON]->(:Jugador) WITH j, SUM(r.volumenTotal) AS volumen ORDER BY volumen DESC LIMIT 10 RETURN j.nickname, volumen
Consulta 4 — Clanes dominantes (fórmula de poder)
Calcula el poder de cada clan combinando riqueza, cantidad de miembros y victorias con pesos distintos.
MATCH (c:Clan) WITH c, (c.riqueza * 0.4 + c.cantidadMiembros * 100 + c.victorias * 50) AS poder ORDER BY poder DESC LIMIT 10 RETURN c.nombre, c.tag, poder

Consulta 5 — Jugadores más influyentes
Cuenta cuántas veces un jugador es mencionado en relaciones entrantes (amigos que lo eligen, socios que comercian con él).
MATCH (j:Jugador) OPTIONAL MATCH ()-[:AMIGO_DE]->(j) OPTIONAL MATCH ()-[:COMERCIA_CON]->(j) WITH j, COUNT(*) AS influencia ORDER BY influencia DESC LIMIT 10 RETURN j.nickname, influencia
Consulta 6 — Clanes con guerras activas
Lista los clanes que actualmente tienen más conflictos activos, usando propiedades de la relación.
MATCH (c:Clan)-[g:EN_GUERRA_CON {activa: true}]->(:Clan) WITH c, COUNT(g) AS guerrasActivas ORDER BY guerrasActivas DESC RETURN c.nombre, guerrasActivas
Consulta 7 — Recomendación de clanes para un jugador
Busca los clanes donde ya están los amigos del jugador, pero a los que él todavía no pertenece.
MATCH (j:Jugador {nickname: $nickname})-[:AMIGO_DE]-> (amigo:Jugador)-[:PERTENECE_A]->(c:Clan) WHERE NOT (j)-[:PERTENECE_A]->(c) WITH c, COUNT(amigo) AS amigosEnClan RETURN c.nombre, amigosEnClan ORDER BY amigosEnClan DESC LIMIT 5
Consulta 8 — Distribución de eventos por tipo
Agrupa y cuenta los eventos del servidor según su tipo (PvP, Construcción, Exploración, etc.).
MATCH (e:Evento) WITH e.tipo AS tipo, COUNT(e) AS cantidad RETURN tipo, cantidad ORDER BY cantidad DESC

⬡ Consultas complejas con recorrido de grafo

Recorrido 1 — Amigos de amigos (2° grado)
Recorre el grafo 2 saltos en profundidad. Encuentra jugadores con amigos en común que aún no son amigos directos — base de cualquier sistema de recomendación social (similar a "Personas que quizás conozcas" de Facebook).
MATCH (j:Jugador {nickname: $nickname})-[:AMIGO_DE*2..2]->(amigo2:Jugador) WHERE NOT (j)-[:AMIGO_DE]->(amigo2) AND j <> amigo2 WITH DISTINCT amigo2 LIMIT 20 OPTIONAL MATCH (amigo2)-[:PERTENECE_A]->(clan:Clan) RETURN amigo2.nickname, clan.nombre
Recorrido 2 — Camino más corto entre dos jugadores
Implementa el algoritmo de búsqueda del camino mínimo directamente en la base de datos usando la función nativa shortestPath. Responde cuántos "grados de separación" hay entre dos jugadores cualquiera (el concepto de los 6 grados de separación de Kevin Bacon). En SQL esto requeriría una consulta recursiva CTE compleja.
MATCH (origen:Jugador {nickname: $origen}), (destino:Jugador {nickname: $destino}), path = shortestPath((origen)-[:AMIGO_DE*]-(destino)) RETURN [n IN nodes(path) | n.nickname] AS camino, length(path) AS grados_de_separacion

5. Neo4j vs Bases de Datos Relacionales

✅ Ventajas de Neo4j en este caso

  • Consultas de grafo nativas: recorridos multi-salto como shortestPath o amigos de amigos en una sola línea Cypher, sin JOINs.
  • Propiedades en relaciones: COMERCIA_CON guarda volumen, fecha y el ítem más comerciado directamente en la arista.
  • Modelo intuitivo: el diagrama de entidades ES el grafo. No hay "traducción" entre el dominio y la base de datos.
  • Rendimiento en traversals: recorrer relaciones es O(1) por nodo, no se degrada con el tamaño total.
  • Cypher legible: el lenguaje de consulta expresa patrones de grafo de forma clara y concisa.

❌ Desventajas / Limitaciones

  • No apta para reportes masivos: agregaciones tipo BI (millones de filas) son más lentas que en PostgreSQL.
  • Menor ecosistema: menos herramientas de reportes y BI nativas comparado con bases relacionales.
  • Curva de aprendizaje: Cypher es un lenguaje nuevo para la mayoría de los equipos.
  • Datos tabulares simples: para datos sin relaciones complejas, una tabla SQL es más eficiente.
  • Menor adopción: menos administradores con experiencia en producción.

7. Conclusión

MineGraph demuestra en la práctica la ventaja de elegir la herramienta correcta para cada problema. Un servidor Minecraft es, en esencia, una red social: jugadores que se conectan entre sí de múltiples formas. Modelar eso como un grafo en Neo4j resultó natural, expresivo y eficiente.

Las consultas más poderosas del sistema — el camino más corto entre jugadores y los amigos de amigos — son triviales en Cypher y habrían requerido lógica recursiva compleja en SQL. Esto evidencia la importancia de analizar el dominio del problema antes de elegir la tecnología de persistencia.

El trabajo integra conocimientos de modelado de datos, lenguajes de consulta, desarrollo backend con Java y Spring Boot, y desarrollo frontend con Angular, aplicados a un caso de uso concreto y funcional.

Stack tecnológico completo: Neo4j 2026 (Graph DB) · Spring Boot 3.2 · Java 21 · Spring Data Neo4j 7 · JWT Security · Angular 17 · TypeScript · vis.js · Chart.js
